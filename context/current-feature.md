### 2026-06-13:

Splash Screen (animated, OS-theme-aware) — Built a two-layer launch experience matching context/screenshots/splash-screen.png. Layer 1: native splash (app.json → expo-splash-screen) with light (#FAFAFA) + dark (#0D0D0D) variants, so the very first frame before JS runs matches the OS theme. Layer 2: an animated React Native splash that takes over once JS mounts, plays the brand motion, then router.replace's onward. Theme is driven by the OS system appearance — added hooks/use-system-color-scheme.ts wrapping useColorScheme from `react-native` (Appearance API), kept deliberately separate from @/hooks/use-color-scheme (which reads the in-app Zustand settingsStore, defaults dark and isn't hydrated at launch). Entry point is a new app/index.tsx (registered in app/\_layout.tsx, headerShown:false) that owns the expo-splash-screen preventAutoHideAsync/hideAsync lifecycle, resolves the destination via lib/getInitialRoute.ts (stubbed to /(auth)/sign-in until Supabase auth is wired — branches on session + onboarding later), and replaces the splash (no back-stack entry). Components under components/splash/: AnimatedSplash (themed container + ignition/exit orchestration + wordmark "CreatorLog" / tagline "Show up. Every day." / v{version} from expo-constants), FlameLogo (gradient flame + breathing ember-bloom glow built from stacked semi-transparent amber circles, no react-native-svg), RisingSparks (6 staggered amber embers drifting up), LoadingShimmer (sweeping highlight band via expo-linear-gradient). All motion uses react-native-reanimated only (withSpring/withRepeat/withTiming; scheduleOnRN from react-native-worklets for the exit→onFinish handoff, replacing deprecated runOnJS). The flame is a single shared asset assets/images/splash-flame.png (1024², gold→amber→orange gradient, transparent, padded; rendered from the Ionicons flame path) used by BOTH the native splash and the animated FlameLogo (via expo-image), so the flame is pixel-identical across layers; FlameLogo accounts for the asset's built-in padding (FLAME_FILL) so the visible flame matches the requested size. Installed expo-linear-gradient; briefly used and then removed @react-native-masked-view/masked-view after switching the flame from a masked gradient to the shared PNG (also dropped the web fallback branch). Deleted the now-orphaned Expo placeholder assets/images/splash-icon.png (zero references project-wide). Regenerated native projects with npx expo prebuild --clean for both platforms — a plain rebuild does NOT overwrite existing splash drawables, which is why the first rebuild still showed the placeholder. Verified on device: native + animated splash render correctly and the OS theme drives both (toggled device-level appearance) on Android (Pixel 9) and iOS (iPhone 17 Pro); flame pixel-identical across native/animated layers. npx tsc --noEmit clean; new files lint clean.
