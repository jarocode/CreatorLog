# Current Feature

## Status

In Progress — Authentication Phase 3 (Apple & Google SSO). See @context/features/authentication-spec.md (Phase 3).

## Goals

- Apple Sign In: wire sign-in/sign-up's existing "Continue with Apple" button (currently a `handleApple` no-op) to `expo-apple-authentication` → `signInAsync` (request `FULL_NAME` + `EMAIL` scopes), then `supabase.auth.signInWithIdToken({ provider: 'apple', token: identityToken })`. iOS-only; hide/disable the button on Android. Capture `fullName` from the first-time credential and pass it as `full_name` user metadata so the `handle_new_user` trigger seeds the profile (Apple only returns the name once).
- Google Sign In: wire the "Continue with Google" button (`handleGoogle` no-op) to `@react-native-google-signin/google-signin` → `signIn()` → `supabase.auth.signInWithIdToken({ provider: 'google', token: idToken })`. Configure with the web/iOS/Android OAuth client IDs; `GoogleSignin.configure({ webClientId })` at startup.
- Ordering: Apple shown before Google on iOS per Apple HIG (already the screen order). Buttons appear on both sign-in and sign-up.
- Service layer: extend `services/auth.ts` with `signInWithApple` / `signInWithGoogle` wrappers returning `{success,data,error}` with friendly errors (handle user-cancellation as a silent no-op, not an error toast). Session lands via `onAuthStateChange`; the route guard sends new users to onboarding, existing users to tabs — same gate as Phase 1/2.
- Config: flip Apple/Google providers to `enabled = true` in `supabase/config.toml` and set the provider credentials (Apple Service ID / Google client IDs) in the Supabase dashboard. Add the `expo-apple-authentication` plugin + entitlement and the Google sign-in plugin/URL scheme to `app.json`.
- Build + verify on device: requires a fresh native dev build (new native deps don't autolink into an existing android/ios dir — `expo prebuild --clean`). Apple round-trip on iOS (real device — Apple auth doesn't work in the simulator reliably), Google round-trip on Android + iOS. `npx tsc --noEmit` + `npx expo lint` clean.

## Notes

- Builds on Phase 1/2 (authStore + `onAuthStateChange` listener + `useProtectedRoute` gate + SecureStore session). SSO just produces a session; no new routing logic needed — the existing guard already branches new vs. returning users by `onboarding_completed`.
- **Blocked on config / credentials:** providers are `enabled = false` in `supabase/config.toml`; needs Apple Service ID + Google OAuth client IDs provisioned in the Supabase dashboard before the flows can be exercised end-to-end. Treat credential provisioning as a prerequisite slice.
- New native deps (`expo-apple-authentication`, `@react-native-google-signin/google-signin`) require a fresh dev build (`expo prebuild --clean` + Metro cache clear), same gotcha hit in Phase 1 with expo-secure-store.
- Apple requires the in-app display name to come from the first sign-in's credential (the name is only returned once); persist it into `full_name` metadata at sign-in time.
- This completes the auth feature (project-overview §4.2 lists Email/Password, Magic Link, Apple, Google as the four required providers).
